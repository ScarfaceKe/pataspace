# PataSpace Property Registration Foundation

This module extends the accepted Master Prompt 1, 2 and 3 foundations. It does not redesign or replace the Kenya-only platform scope, official brand standards, authentication system, supported categories or trust principles.

## Purpose

The Property Registration Foundation allows authorised users to register rental properties into PataSpace through a simple, guided, accurate and trustworthy workflow. Future House, Shop, Office and Event Hall registration prompts must inherit and extend this foundation.

## Who can register properties

The following users are authorized to register properties on PataSpace:

- 👑 Property Owner
- 🏢 Property Manager
- 🤝 Leasing Agent

Customers cannot register properties.

## Registration Responsibilities

The registration workflow adapts based on who is registering the property.

### 👑 Property Owner

The Property Owner may:

- Register their own property.
- Assign or link a Property Manager.
- Assign or link a Leasing Agent.
- Manage their property through the Owner Dashboard.

### 🏢 Property Manager

The Property Manager may:

- Register properties they manage.
- Link the Property Owner.
- Link the Leasing Agent, if applicable.
- Manage vacancies and perform daily vacancy confirmations.

### 🤝 Leasing Agent

The Leasing Agent may:

- Register properties on behalf of the Property Owner.
- Link the Property Owner.
- Link the Property Manager, if one already exists.
- Participate in the leasing workflow according to their assigned permissions.

This reflects real-world property management in Kenya, where a property's contact number is often that of the Leasing Agent, and the Leasing Agent may be responsible for bringing the property onto the platform.

## Guided registration philosophy

Property registration is guided, step-by-step, mobile-first, easy to understand and professional. It is split into logical screens and must never overwhelm users with one very long form.

## First registration screen

The workflow starts with exactly four clean category cards:

1. 🏠 House
2. 🏪 Shop
3. 🏢 Office
4. 🎉 Event Hall

Selecting one starts the matching property registration workflow. Future prompts will define each detailed workflow.

## Location foundation

Every property collects:

- County
- Town / City
- Estate / Area / Neighbourhood
- Street, if applicable
- Landmark, optional

The large description field is labelled:

> Tell us anything else that will help people find the right home, shop, office or hall.

## Kenya location intelligence

PataSpace remains Kenya-only. The platform recognises Kenyan counties, cities, towns, estates and neighbourhoods. If a Property Manager enters a location not yet recognised, the registration is accepted and quietly flagged for review. The system does not tell the user, “We don't recognise this area.”

The AI Admin Assistant is represented as quiet background support for identifying and validating new locations.

## Ownership and vacancies

During registration, the user specifies their registration relationship, including owner, property manager, or leasing agent where applicable.

The workflow asks whether the property currently has vacant units. If yes, basic vacancy information is collected and the property is prepared for vacancy verification. If no, the property can still be registered, but no units are published until vacancies become available.

## Daily vacancy verification foundation

Every published vacant unit is prepared for the future vacancy verification system, including daily confirmations, grace periods, Waiting for Verification, search priority and Platform Health Monitor workflows.

## Photos

The foundation supports property photo selection. Photos should be high quality, clear and relevant. Future prompts will define exact photo rules for each property category and vacancy type.

## Status management

Every property has a status foundation. Current status states include:

- Draft
- Active
- Waiting for Verification
- Occupied

Future prompts will define detailed status transitions.

## Validation and quiet admin assistance

Before saving, the platform validates required information, logical consistency, duplicate property candidates and obvious mistakes. Quiet review flags prepare the AI Admin Assistant and Platform Admin workflows without making the user feel questioned by AI.

## Saving and completion

The user can Save as Draft, Continue Later by returning to the workflow, or Submit Registration. After successful submission, the user sees: “Property successfully registered.”

## Vacant Unit Identification

Every vacant unit registered on PataSpace must have its real-world unit identifier recorded exactly as it appears on the property.

This applies to:

- 🏠 Houses
- 🏪 Shops
- 🏢 Offices
- 🎉 Event Halls

The Property Owner, Property Manager or Leasing Agent should enter the unit identifier exactly as it exists on the property. Examples include A1, A2, B5, K7, Shop 14, Office 203, Hall A, Hall B, Stall 3, Unit 12 and Room 7.

The platform must never generate or force its own numbering. It preserves the actual unit identifier used on the property.

This identifier becomes the official reference throughout PataSpace, including Unlock This Listing, Verified Access, Viewing Requests, Property Reviews, Notifications, Vacancy Management, Daily Vacancy Confirmation, Search Results, Search Matching, Admin Dashboard and AI Admin Assistant.

All future registration modules inherit this platform-wide rule from the Property Registration Foundation.

## Electricity Information

Electricity availability is a mandatory property registration requirement on PataSpace because it is an important factor when tenants choose a property.

This requirement applies to:

- 🏠 Houses
- 🏪 Shops
- 🏢 Offices

It does not apply to 🎉 Event Halls because event halls follow a different matching philosophy.

During registration, ask: **Is electricity available?** Options are Yes and No.

If Yes, ask: **How is electricity billed?** Options are Individual Meter, Shared Meter, Included in Rent and Other. If Other is selected, the Property Owner, Property Manager or Leasing Agent can briefly describe the billing arrangement.

The registrant may also provide useful information regarding electricity supply. This information becomes part of the property's profile and will later be used by Match Engines so prospective tenants understand the electricity setup before unlocking a listing or requesting a viewing.

Electricity information is collected only once for Houses, Shops and Offices, and inherited by future modules including House Match, Shop Match, Office Match, Viewing Workflow, AI Admin Assistant and Property Details. It is not collected for Event Halls and is not considered by the future Hall Match Engine.

## Registration User Experience Standard

Every property registration workflow on PataSpace must be designed as an intelligent guided experience rather than a traditional form.

This applies to:

- 🏠 Houses
- 🏪 Shops
- 🏢 Offices
- 🎉 Event Halls

Wherever possible, the platform should use toggle buttons, selectable chips, option cards, multi-select choices and Yes / No switches instead of requiring users to type information manually.

For example, Water Available should be presented as simple choices such as Daily, Specific Days, Purchased and No Water. Electricity Available should be presented as Yes or No. If Yes is selected, the next relevant question should appear immediately: How is electricity billed? Options should include Individual Meter, Shared Meter, Included in Rent and Other.

This adaptive behaviour applies throughout every registration workflow. Questions should appear only when they become relevant based on previous selections, so users feel they are making simple choices instead of filling out long forms.

Text input fields should only be used where information cannot reasonably be selected from predefined options, such as Property Name, Landmark, Property Description and Other when selected.

All future property registration modules inherit this user experience standard from the Property Registration Foundation.

## Customer Access Control Standard

Every property returned in House Match, Shop Match, Office Match or Hall Match displays only permitted information before the customer purchases access.

Before access is purchased, a public property card may display only the two cover photos selected during registration, Property Summary, clearly labelled AI Summary, Why This Property Matches, Unlock This Listing with the approved price, and a Verified Access recommendation when the Founder-approved recommendation rules are satisfied.

Before access is purchased, PataSpace must never display Property Owner phone number, Property Manager phone number, Leasing Agent phone number, WhatsApp contact, Request Viewing through the platform, or any direct contact information that allows communication outside PataSpace.

Only after the customer successfully purchases Unlock This Listing or Verified Access may the platform unlock all property photos, contact phone number, calling, WhatsApp and Request Viewing through the approved Viewing Workflow.

This standard is mandatory for Houses, Shops, Offices and Event Halls. No property type may bypass it.
